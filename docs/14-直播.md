## 5分钟速读

> 先扫这几条再往下精读；细节与证据等级见正文。

- 直播是 2026 增长最快的消费场景之一：官方称 2026-08 每天有 6 亿+ 登录用户观看直播内容。【官方】第三方统计显示 YouTube 约占全网直播时长一半、拿走几乎全部增量。【二级】
- 官方默认横竖「双流」同播，**只有竖版进 Shorts 信息流**——一场直播自带一条 Shorts 发现入口。【官方】
- 直播是最难批量伪造的内容形态：几小时无剪辑的真人时间，建立信任最快。【行业实践】
- 直播不替代长视频：先保住可预测的长视频节奏，再加直播（[02 §6](02-冷启动0到1000.md) 产能表不变）。
- 2026–2027 官方路线：React Live **年内**扩展到长视频；2027 起 Go Live Together 匹配、Live Showdowns、实时自动配音——以 Studio 实际可用为准，上线前不写进 SOP。
- 读数：进场即计公开观看（[07 §6.0](07-频道装修与Studio.md#_6-0-观看数口径与替代指标) 口径）；看并发曲线、平均观看时长、聊天参与与回访。

## 1. 直播在 2026 的位置

**【官方 · YouTube Blog 2026-09-23】** 2026 年 8 月，每天有超过 **6 亿**登录用户观看直播内容（含回放）；直播观看时长中 **40% 以上**来自创作者母国以外的观众。（[SOURCES #152](SOURCES.md)）

**【二级 · Streams Charts 2026 Q2】** 全平台直播观看约 314 亿小时，创纪录；其中 YouTube 约 156 亿小时（同比 +14.8%），TikTok Live 与 Twitch 持平，Kick 小幅增长——**YouTube 约占一半，且拿走了几乎全部增量**。第三方统计口径，非平台数据（[#155](SOURCES.md)）。

**【行业实践】** 对小创作者的含义有两层：

1. **供需**：公开讨论中反复出现的观察是，YouTube 直播的「观众 ÷ 开播者」显著优于以直播为主业的平台。这类数据多为工具厂商自报、不可核验，但方向与上面的官方与第三方数据一致（[#156](SOURCES.md)，只取方向、不引倍数）。  
2. **信任**：当 AI 把脚本、剪辑、配音的成本压到趋近于零，「几小时不可剪辑的真人时间」成了最难伪造的东西。直播站在 [09 §4](09-变现与合规红线.md)「不真实内容」红线的**另一端**。

> 本指南的立场不变：直播是第二条发现路径与信任引擎，**不是**长视频目录的替代品。

## 2. 谁该开、谁先别开

| 适合先开 | 先别开 / 晚点开 |
|----------|-----------------|
| 教学 / 问答 / 答疑型：观众带着问题来，直播就是「实时 FAQ」 | 还没有可预测的长视频节奏（连周更都保不住） |
| 游戏、创作过程、陪伴型：内容天然是「过程」 | 内容高度依赖后期（动效、叙事剪辑），直播只剩「聊聊」 |
| 已有核心粉、评论区活跃：有人会来 | 零订阅零目录：直播间没人，先用长视频 + Shorts 建基础 |
| 想加速「真人信任」的真人出镜品类 | 不愿露脸露声、也没有可展示的过程 |

**【行业实践】** 冷启动期的折中：**每月 1 场、固定时段、固定主题**（如「本月视频答疑」），当作与观众的约会，而不是产能主战场。

## 3. 第一场直播的最低配置

设备与网络原则沿用 [设备与剪辑起步](设备与剪辑起步.md)：**听得清 > 看得清 > 画面美**。【行业实践】

- **音频优先**：直播没有后期救场，麦克风与环境噪音是第一要务。  
- **网络**：上行稳定比峰值高重要；有线优于 Wi-Fi；先以保守码率稳定开播，再逐步上调（具体码率以 Studio 推流建议与你的编码器为准）。  
- **两种开播方式**：Studio「Go live」/ 手机直接开播；或第三方编码器（OBS 等）推流——后者可用双流（§4）。  
- **开播前自检**：预约页已建、标题缩图已上（§5）、聊天规则与版主已设（§9）、能看到自己的聊天与并发数。  
- **【官方 Blog】** 首次开通或首次直播可能有等待期（[06 §7](06-Shorts漏斗.md) 所引官方 Blog，[SOURCES #14](SOURCES.md)；具体以 Help 与 Studio 提示为准）。

## 4. 双流：一场直播的 Shorts 入口

**【官方 · Help「Get started with live streaming」】**（[SOURCES #151](SOURCES.md)，2026-10-21 核对）

- 从 Live Control Room 开播时，**默认同时**以横屏（16:9）与竖屏（9:16）两种格式直播；竖版默认为横版的**中心裁切**，可改为「适配手机宽度」「上下堆叠」等布局，并可**在直播中继续调整**竖版布局。  
- **第三方编码器**：在 Stream 页把 Auto 改为 Encoder，以 RTMP(S) 推送，**为竖版单独选一把串流密钥**；你需要自行保证横竖内容一致、各格式送到对应密钥。  
- **只有竖版会出现在 Shorts 信息流**并可被上下滑动发现；手机端从 Shorts 流进来的观众看到竖版，其他观众看到横版。  
- 订阅者只收到**一条**开播通知、同一个直播链接；横竖观众**共用同一个聊天**。  
- 分析：直播中与结束后先看合并数据，竖版单独数据约 24 小时后出现。  
- **限制**：开播后**不能再追加**竖版；竖版目前缺少可点击的聊天链接、直播中插/前贴广告、4K、首映、直播重定向；会员与赠送会员两端都可用。  
- 不想要竖版：在 Stream settings 关闭 Dual stream。

**对你的含义**【行业实践】：双流让一场直播自动获得一条 Shorts 发现入口——这正是 [06 §3 官方四步](06-Shorts漏斗.md) 的 Step 4。要让它有用：开播前把竖版布局调到「主体在中间、字不被裁掉」，并在横版画面里给竖版留出安全区。

## 5. 直播也要包装

直播在 YouTube 的分发同样经过「曝光 → 点击 → 留存」漏斗（[01](01-推荐系统心智模型.md)），所以 [04 包装](04-标题封面与包装.md) 的铁律一条不少：【行业实践】

1. **预约页**：提前建预约直播，写清「几点、讲什么、给谁」；可用社区帖投票预热（遵守 [02 §7.2](02-冷启动0到1000.md) 的互动边界）。  
2. **标题**：重要词靠前 + 可兑现；避免「随便聊聊」「来坐坐」这类零信息标题。  
3. **缩图**：按 [04 §6.2](04-标题封面与包装.md) 规格做一张专门的直播缩图，不要用自动截帧。  
4. **开场**：直播的「前 15 秒」是**前 5 分钟**——先说今天解决什么、几点结束、怎么提问，再等人进来；不要「等人齐了再开始」。  
5. **结束**：口播下一场时间，并指向一条长视频。

## 6. 回放是资产

- 直播结束后回放通常会保留在频道（是否公开、是否自动归档以 Studio 设置与 Help 为准）；回放的留存曲线同样有 [05 §2](05-脚本留存与完播.md) 的 Spike / Dip。  
- **Spike 剪 Shorts**：回放里的高光段按 [06 §5](06-Shorts漏斗.md) 剪成 Shorts，Related Video 挂回**长视频**而不是回放（回放通常太长、开场慢）。  
- **回放 → 长视频**：答疑类直播可剪成「一问一答」的长视频；一场直播 = 多条目录内容。  
- 回放时长长、开场慢，会拉低频道整体 AVP 观感——用自己同类内容的基线比，不要与短片横比（[07 §6.4](07-频道装修与Studio.md)）。

## 7. 直播怎么读数

- **口径**：2026-08-24 起，观众进入直播即计一次公开观看（[07 §6.0](07-频道装修与Studio.md#_6-0-观看数口径与替代指标)）；公开数字不再反映停留。【官方】  
- **看什么**（Studio 直播分析，名称以界面为准）【行业实践】：**并发观众曲线**（哪一段掉人 = 直播版 Dip）、**平均观看时长**、**聊天参与**（发言人数 ÷ 观看人数）、**新订阅**，以及回放的留存。  
- **双流拆分**：竖版单独数据约 24 小时后可见——用它判断 Shorts 入口是否真的带来陌生人。【官方 #151】  
- **周复盘**（[08 §7](08-发布节奏实验与复盘.md)）加一行：本周直播的并发峰值、掉人点、转化到长视频的来源数。

## 8. 2026–2027 直播新功能地图

**【官方 · YouTube Blog 2026-09-23（Made on YouTube）】**（[SOURCES #152](SOURCES.md)）

| 功能 | 官方描述 | 时间（官方口径） | 对你的含义【行业实践】 |
|------|----------|------------------|------------------------|
| **Watch With / React Live** | 创作者可对他人内容做实时反应直播；由直播扩展到「所有合资格长视频」。反应者保留直播广告与粉丝资助收入；原创者获署名、Studio 观看计入，并可控制哪些视频可被反应 | 「starting later this year」 | 两面：可借大流量内容的观众；你的内容也可能被别人反应。开关的独立 Help 页本站未找到，以 Studio 设置为准 |
| **Go Live Together · 创作者匹配** | 浏览正在直播的创作者，或进入快速匹配队列自动与相似创作者共播 | 「in early 2027」 | 小频道的「借流」路径；共播本身也是信任背书 |
| **Live Showdowns** | 共播中的实时对战，观众用聊天 / 礼物 / Super Chat 为创作者推分 | 「coming in 2027」 | 粉丝资助玩法；注意 §9 的互动边界 |
| **直播实时自动配音** | 观众以偏好语言实时收听 | 试点「starting in early 2027」 | 华语创作者的潜在出海入口；官方称 40%+ 直播时长本就跨国 |

全部以 Studio 实际可用与 Help 为准；**上线前不要写进 SOP**（与 [07 §7](07-频道装修与Studio.md) 对「即将推出」功能的态度一致）。

## 9. 直播的合规与红线

直播不改变任何红线，只是让它们更「实时」：

- **音乐与素材**：直播同样受版权与 Content ID 约束，且没有后期可剪；用音频库或已授权音乐（[09 §7](09-变现与合规红线.md)）。  
- **聊天**：设置审核词与版主；**禁止**在直播里组织互粉互赞、「刷 Super Chat 换承诺」等虚假互动（[09 §6](09-变现与合规红线.md)）。  
- **付费推广**：直播中的赞助口播同样要勾选付费推广并口头披露（[09 §9.2](09-变现与合规红线.md)）。  
- **真实故事 / 敏感题材**：即兴评论没有「再剪一刀」的机会——敏感题材先过 [09 §8](09-变现与合规红线.md) 的伦理六问。  
- **未成年人与隐私**：露脸、露址、第三方入镜的边界在直播里更容易失守。

## 10. 失败模式

| 失败 | 症状 | 纠正 |
|------|------|------|
| 「随便播播」 | 无预约、无标题、无缩图，开场十分钟等人 | §5 五件事做完再开播 |
| 直播吃掉长视频 | 周更长视频断了，直播场次却在涨 | 回到 [02 §6](02-冷启动0到1000.md) 产能表：先保长视频 |
| 把 YouTube 直播当成别处的复刻 | 只做横屏、不管竖版、不剪回放 | 开双流 + 回放剪 Shorts（§4、§6） |
| 聊天区变互刷群 | 「关注回关」「刷礼物置顶」 | 虚假互动红线（[12 §6.1](12-反例与失败模式.md)） |
| 回放堆满频道页 | 首页全是 3 小时回放，新观众看不懂频道做什么 | 回放设未列出或归入独立播放列表（[07 §2](07-频道装修与Studio.md)） |

## 11. 本章检查清单

- [ ] 直播是「第二路径」，长视频节奏未被挤掉  
- [ ] 第一场：固定时段、固定主题；预约页 + 标题 + 缩图齐  
- [ ] 开播前检查 Dual stream 状态与竖版布局（§4）  
- [ ] 开场前 5 分钟说清「解决什么 / 几点结束 / 怎么提问」  
- [ ] 结束口播下一场 + 指向一条长视频  
- [ ] 回放：Spike 剪 Shorts，Related 挂长视频  
- [ ] 读数看并发曲线、平均观看时长、聊天参与，不看公开观看数  
- [ ] 聊天规则与版主已设；音乐已授权；赞助已披露

## 本周作业

> 2–5 件可完成的具体动作；做完打勾，再进下一章。

1. [ ] 决定你属于 §2 哪一栏；若「先别开」，写下触发条件（如：长视频连续周更 8 周后）。  
2. [ ] 若开：建一个预约页（标题 + 按 04 §6.2 规格的缩图），固定到两周后的某个时段。  
3. [ ] 做一次不公开的测试直播，用手机看竖版画面：字和主体是否被裁掉。  
4. [ ] 结束后 48 小时内：从回放标出 1 个 Spike，剪成 Short 并挂 Related 到一条长视频。
